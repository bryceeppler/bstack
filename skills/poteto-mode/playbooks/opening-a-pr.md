### Opening a PR

Invoked at the end of every other playbook.

Work from a git worktree off trunk, and keep unrelated work out of it. Rebase into small, landable commits. Run `/deslop` over the diff before commit.

Title: `type(scope): subject`, naming a real symbol when one carries the change. Body: a one-minute briefing under 40 lines with these `##` headings in order, dropping empty ones: `## Why`, `## What changed`, `## Scope`, `## Tradeoffs` (only rejected alternatives a reviewer would otherwise ask about), `## Blast Radius`, `## Verification`, `## Proof pass`. When the repo generates `## Verification` from recorded runs (for example a `--summary` block that a CI check compares against statuses on the head), paste the generated block and write nothing else in it. `## Proof pass` is one line, present whenever the pass below ran: the verdict, the model that gave it, the short head it covers, and each finding as fixed or declined with the reason. A declined finding keeps the reviewer's label.

**Size and stacks.** One PR per shippable change, because every new head of a ready PR restarts billed CI. Work that merges together in one sitting is one PR, or one integration branch merged once. Stack only when each layer needs its own review before the next can proceed. Build and land a stack with `gh stack` per the `gh-stack` skill, never with `gh pr create --base <feature-branch>` or `gh pr merge`. Do not rebase a PR onto its base until it is next to merge.

**Proof pass.** A PR that changes product code gets one independent proof pass on its final head, while it is still a draft. Skip it when the diff holds only docs, dependency pins, config or repo tooling, and on a branch Shipping, Autopilot-full or Autopilot-stack already verifies. Spawn one `delegate_task` child on the `swarm workers` model, with that line's fallbacks per the **swarm** skill's step 3. Its whole brief is the absolute path of `references/proof-pass.md` to read in full, then the repository, the PR number, the base ref, the head SHA and an evidence directory at `~/.local/state/pstack/proof/<repo>-<branch>/`. It does not open with `poteto-agent.md`. Rerun each finding's command yourself before you act on it. Fix a finding the diff caused or the PR claims to fix. Decline one trunk already has that the diff neither copies nor newly reaches, and park it as a follow-up. The verdict covers one patch. After any later code change, one fresh reviewer checks only that change and the open findings at the new head, and the patch-id rule in `playbooks/shipping.md` decides whether a rebase needs one. A head with a verdict gets no second full pass. A reviewer of the author's model family says so in the `## Proof pass` line.

**Readiness.** Open a PR as a draft with `gh pr create --draft`, because a draft runs no CI. Call `link_pull_request` with the PR URL at once, for every layer of a stack. Mark it ready exactly once, when its final head has passed the repo's local checks, its gate and its proof pass. After that, batch every fix into one push. A stack layer above the bottom stays a draft until the layer below merges, and an integration branch's PR stays a draft until the branch is complete and next to merge. A subagent that opens a PR links it and reports the URL, and its parent links that URL too.

Opening a PR does not start a babysit. A PR the thread's own finish condition needs green, ready or merged, such as a run PR, is waited on through the **babysit-pr** skill once it is ready. Call `unwatch_pull_request` before you hand a PR back to the user.
